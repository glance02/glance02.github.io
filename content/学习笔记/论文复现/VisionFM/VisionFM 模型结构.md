# VisionFM 模型结构（新手向）

> **一句话总结**：VisionFM 不是一个"大一统"的巨型模型，而是 **8 个各自会看图的"眼睛"（编码器）+ 一堆针对不同问题的"小脑袋"（解码器）** 的组合。换任务只需要换小脑袋，眼睛不用重学。

官方代码：https://github.com/ABILab-CUHK/VisionFM

## 0. 先补三个基础概念

### 概念 1：编码器（encoder）和解码器（decoder / head）

- **编码器**：把一张图片"翻译"成一串数字（叫**特征** feature）。它只负责"看懂这张图"，不负责回答具体问题。
- **解码器**：拿这串数字去回答一个具体问题，比如"有没有糖网""血管在哪些像素上"。

> 类比：编码器 = 一个训练多年的眼科医生的**眼睛和视觉皮层**；解码器 = 一张**具体问题的答题表**。想换个问题，换张答题表就行，眼睛不用重新培养。

### 概念 2：预训练 → 微调 → 冻结

| 步骤 | 做什么 | 需要人工标注吗 |
| --- | --- | --- |
| 预训练 pretrain | 用海量图片练"看图基本功" | **不需要** |
| 微调 finetune | 用少量有标注数据学具体任务 | 需要，但可以很少 |
| 冻结 frozen | 微调时把编码器参数锁死，只训练解码器 | —— |

VisionFM 微调时**编码器是冻结的**（代码里 `model.eval()`，优化器只收 head 的参数）。好处：标注数据再少也不容易过拟合，单张显卡就能跑。

### 概念 3：ViT 输出两种东西

一张 224×224 的图 → 切成 14×14 = 196 个小块（**patch**）→ 每块变成一个向量（**token**）→ 过 12 层 Transformer。出来能用的信息有两种：

- **[CLS] token**：1 个 768 维向量，相当于"整张图的总结" → 适合**分类、回归**。
- **196 个 patch token**：每个都对应图上的一小块位置 → 适合**分割、找关键点**（需要知道"哪里"）。

## 1. 整体结构图

```text
                        +-- Fundus 编码器 --+
   一张眼科图片 ------> |    OCT  编码器    |   8 个 ViT-B/16，彼此完全独立
                        +-- ... UBM 编码器 -+   （预训练好之后全部冻结）
                                   |
                                   v
             +---------------------+---------------------+
             |                                           |
        [CLS] token                                patch token
      (取最后 4 层拼接)                          (取第 3/6/9/12 层)
             |                                           |
   +---------+---------+---------+              +--------+--------+
   |         |         |         |              |                 |
 分类 MLP  回归 MLP  预测头      |          分割解码器        关键点解码器
(疾病诊断)(38项指标)(青光眼+时间)          (UNETR 风格)      (热力图 argmax)
```

**记住两条正交的设计线**：

1. **编码器按"模态"分**（眼底照、OCT、B 超……各一个）
2. **解码器按"任务"分**（分类、分割、回归……各一个）

所以论文说的"可扩展性"就是：想支持新设备 → 再预训练一个编码器；想支持新任务 → 再训一个小解码器。原有部分完全不用动。

## 2. 编码器：8 个 ViT-B/16

### 2.1 规格

| 项目 | 配置 | 通俗解释 |
| --- | --- | --- |
| 架构 | ViT-Base，patch 16 | 把图切成 16×16 的小块 |
| 层数 / 特征维度 / 注意力头 | 12 层 / 768 维 / 12 头 | 标准 ViT-B |
| 输入尺寸 | 224×224（分割任务用 512×512） | 分割对细节敏感，所以放大 |
| 参数量 | 约 8600 万 | 而解码器通常只有几百万 |
| 覆盖模态 | 眼底照、OCT、FFA 荧光造影、裂隙灯、B 超、外眼照、MRI、UBM | 共 8 种 |
| 预训练数据 | 340 万张图、56 万人 | 关键是**全部无标注** |

### 2.2 为什么每个模态要单独训一个编码器？

因为不同模态的图像长得完全不一样：眼底照是彩色血管网，OCT 是灰度断层切片，B 超是一片噪声斑点。硬塞进同一个编码器会互相干扰。分开训，每个都能把本模态的"基本功"练扎实。

- 代价：不能做"同一个人的多模态融合"
- 好处：**不需要任何配对数据**（配对数据在医学影像里极难拿到）

### 2.3 iBOT 自监督：没有标注怎么练？

两个"小游戏"同时进行：

**游戏 1：完形填空（MIM，masked image modeling）**
随机挡住一部分 patch（遮挡比例 0~0.3），让模型猜被挡住的地方是什么。就像遮住眼底图的一小块，让它推断那里应该有什么结构。

**游戏 2：师生自蒸馏（self-distillation）**
同一张图做两种不同的裁剪/增强，分别喂给"学生网络"和"老师网络"，要求学生的输出去逼近老师的输出。
关键点：**老师不是另一个模型，而是学生自己参数的滑动平均（EMA，momentum = 0.996）**。所以老师更新得很慢、很稳，不会跟着噪声乱跳，能提供相对可靠的"参考答案"。

> 对齐时用的是一个 8192 维的投影头（`out_dim=8192`），这个头**只在预训练时用，之后直接扔掉**，下游只保留 ViT 主干。

正因为"标签是模型自己造的"，才能吃下 340 万张无标注图 —— 这就是 VisionFM 少样本（few-shot）能力强的根本原因。


## 3. 特征怎么取？（新手最容易懵的一步）

代码里有两个开关，决定送给解码器的向量长什么样：

| 开关 | 含义 | 输出维度 |
| --- | --- | --- |
| `--n_last_blocks 4` | 不只用最后一层，把**第 9~12 层的 CLS token 拼起来** | 4×768 = **3072** |
| `--avgpool_patchtokens 1` | 改用**最后一层 196 个 patch token 求平均** | **768** |

- 为什么拼 4 层？浅层偏纹理、深层偏语义，拼一起信息更全，让解码器自己决定用哪层。
- 拼接后的 `[B, 4, 768]` 会先过一个 **BatchNorm2d**（把 4 个 block 当作 4 个"通道"做归一化，稳定数值），再展平成 3072 维。

## 4. 解码器：5 类任务，逐个拆

### 4.1 分类 head（`ClsHead`）—— 疾病诊断 / DR 分级

```text
3072 维特征 --> Linear 1536 --> GELU --> Dropout(0.1)
            --> Linear  768 --> GELU --> Dropout(0.1)
            --> Linear  类别数  --> logits
```

就是一个三层小 MLP。损失函数分两种，**这一点非常重要**：

| 情况 | 用什么损失 | 为什么 |
| --- | --- | --- |
| 多分类互斥（DR 分级 0~4，只能是其中一级） | `CrossEntropyLoss` | softmax，只允许一个正确答案 |
| 多标签共存（8 种病可以同时得） | `BCEWithLogitsLoss` | 每个病各自做 sigmoid 二分类 |

多模态分类的总损失是加权和：

```text
loss = 5*DR分级 + DR + 青光眼 + AMD + 白内障 + 5*高血压视网膜病变 + RVO + 近视 + 视网膜脱离
```

（DR 分级和高血压视网膜病变权重 ×5，因为它们更难、临床上更重要。）

> 对照你日志里的坑：`num_labels=1` 时代码自动走 BCE 分支，`num_labels>1` 走 CE 分支。所以做二分类时，**标签文件的格式必须跟着改**（从"一个类别编号"改成"0/1"），否则会报错或者分数虚高。

### 4.2 模态无关（MA）分类：两阶段训练

**阶段 1 — 离线抽特征**（`evaluation/extract_features.py`）
用各模态的编码器把每张图跑一遍，把 3072 维特征存成 `.pickle` 文件。

**阶段 2 — 混合训练一个 head**（`evaluation/train_cls_multi_decoder.py`）
把 Fundus 特征目录和 OCT 特征目录**倒进同一个数据集**，用**同一个 13 维 head** 一起训练（13 = 5 个 DR 分级 + 8 个疾病二值）。

为什么要先抽特征存下来？因为编码器是冻结的，同一张图每次算出来的特征都一模一样 → 存下来就不必每个 epoch 都重跑一遍 ViT。**训练速度从小时级降到分钟级**，batch size 能开到 4096~8192。

> **⚠️ 重点纠正（对照你的日志）**
> 你之前记录"多模态分类解码器需要同一患者/同一只眼的不同模态数据"——**代码里不需要**。
> `ClsFeats` 这个 Dataset 只是把各个模态的特征文件**平铺成一个列表**，每条样本仍然是"一张图 + 一个 13 维标签向量"。
> 所谓"模态无关"指的是：**同一个 head 能同时吃下来自不同模态编码器的特征**，而不是把一个人的多种影像融合起来判断。

### 4.3 回归 head（`RegHead`）—— 38 项全身指标

```text
3072 维特征 --> Linear 768 --> GELU --> Dropout --> Linear 38 --> 38 个连续数值
```

输出的是血尿酸、肌酐、血糖、血脂等 38 个**连续数值**（不是分类）。

评价指标 **NRMSE**（归一化均方根误差）：
- ≈ 1.0 表示"跟直接用训练集平均值去猜差不多"
- < 1.0 才算真的比瞎猜强

论文报的是 1.001，说明这个任务其实非常难，作者自己也承认达不到临床可用标准。

### 4.4 青光眼进展预测 head（`ForecastHead`）—— 唯一带"时间"的结构

```text
眼底图 --> ViT --> patch token 求平均 (768 维)
                                        \
                                         + --> Linear --> 1 个 logit --> BCE(pos_weight)
                                        /
随访间隔天数 --> 正弦位置编码 (768 维) --
```

两个新手要点：

1. **正弦位置编码**：Transformer 里表示"这是第几个词"的经典技巧（用不同频率的 sin/cos）。这里借来表示"过了多少天"（`--max_len 6500`，即支持 6500 天以内的间隔），让网络把时间当成一个连续量参与计算。
2. **`pos_weight`**：进展了的病人（正样本）比没进展的少 → 给正样本的损失乘一个更大权重，缓解类别不平衡。

### 4.5 分割 head（`Unetr_Head`）—— UNETR 风格

**要解决的问题**：ViT 吐出来的是 196 个一维向量，而分割需要的是一张 H×W 的掩码图。
**解决办法**：把向量"还原"成特征图，再逐级放大回原图尺寸。

```text
输入：ViT 第 3 / 6 / 9 / 12 层的 patch token  +  原图

第1级： 第12层 上采样x2      (+)  第9层 上采样+卷积      --> 拼接 --> 卷积
第2级： 上一步 上采样x2      (+)  第6层 上采样+卷积x2    --> 拼接 --> 卷积
第3级： 上一步 上采样x2      (+)  第3层 上采样+卷积x3    --> 拼接 --> 卷积
第4级： 上一步 上采样x2      (+)  原图 经 CNN 分支       --> 拼接 --> 卷积
输出 ： 1x1 卷积 --> num_classes 通道掩码（尺寸和原图一致）

(+) = 把两份特征在通道维度拼起来（concat），(+) 左边的"上一步"还会先反卷积放大 2 倍
```

（通道数：base channel = 32，逐级为 128 → 64 → 32 → 16）

三个关键概念：

- **反卷积 `ConvTranspose2d(stride=2)`**：每过一次，分辨率放大 2 倍。
- **skip connection（跳连）**：把编码器浅层 / 原图的**高分辨率细节**直接接到解码器对应尺度上。因为一路下采样会丢边界细节，跳连负责把细节补回来 —— 这是 U-Net / UNETR 的精髓，也是它分割细血管比纯 ViT 强的原因。
- **损失 `DiceFocalLoss`**：
  - Dice 直接优化"预测区域和真实区域的重叠率"，对前景面积极小的情况（比如细血管）很友好；
  - Focal 让模型不要在海量简单的背景像素上浪费注意力。

### 4.6 关键点检测（UBM 前房角 3 个点）

**直接复用 4.5 的分割 head**，只把 `--num_labels` 设成 3 → 输出 3 张热力图，每张对应一个关键点，图上**最亮的位置（argmax）就是预测坐标**。误差用欧氏距离衡量（论文：VisionFM 4.90 px，U-Net 12.85 px）。

> 这是个很常用的技巧：**把"回归坐标"改成"预测热力图"**。直接回归 (x, y) 数值难学；热力图保留了空间结构，好学得多，而且天然支持多个点。

## 5. 这套设计聪明在哪（三条）

1. **模态解耦** → 不需要配对数据，就能覆盖 8 种设备；加新模态 = 加一个编码器。
2. **任务解耦 + 冻结骨干** → 每个任务只训几百万参数的小 head，单卡可跑，few-shot 也不易过拟合。
3. **自监督把基本功提前练好** → 论文里 one-shot（只用 1 张标注图）的 OCT 分层分割就能超过 U-Net 的 ten-shot（Dice 77.54% vs 76.07%）。

## 6. 新手 FAQ

**Q1：编码器都冻结了，为什么还能学得好？**
"看懂眼科图像"这件事已经在 340 万张图上学完了；下游任务只是"把已有特征映射到标签"，一个小 MLP 就够。反过来，如果解冻编码器，标注数据不够时很容易过拟合，甚至把预训练学到的知识"忘掉"（catastrophic forgetting）。

**Q2：为什么分类要取最后 4 层的 CLS 拼接，而不是只用最后一层？**
最后一层最抽象（语义强），前面几层还保留着中层结构信息。拼接起来让 head 自己挑，代价只是输入维度变成 4 倍。

**Q3：我用随机生成的数据训，F1 只有 0.12，是不是代码写错了？**
不是，很正常。随机图的像素和标签之间**没有任何真实关联**，head 学到的全是噪声；而且 13 个标签里绝大多数是 0，F1 天然很低。随机数据的用途只是**验证代码流程能不能跑通**，不是验证精度。

**Q4：显存主要花在哪？**
编码器的**前向推理**（8600 万参数）。反向传播只发生在 head 上，所以比"全量微调"省很多显存。多模态那条路更进一步：特征离线存盘，训练时连编码器都不用加载。

**Q5：为什么我的 OCT 二分类 F1 接近 100%？**
先看测试集有多少张图。测试集太小时，几十个样本全对就能到 100%，置信区间会非常宽，这种数字没有参考价值（论文里所有指标都带 95% CI 就是这个原因）。

## 7. 术语速查表

| 术语 | 通俗解释 |
| --- | --- |
| patch | 图像被切成的小方块，ViT 的最小处理单位 |
| token | patch 变成的向量 |
| [CLS] token | 代表整张图的"总结向量" |
| feature / embedding | 模型输出的那串数字 |
| iBOT | 预训练方法 = 完形填空 + 师生自蒸馏 |
| MIM | 遮住一部分 patch 让模型猜（masked image modeling） |
| EMA teacher | 老师网络 = 学生参数的滑动平均，更稳定 |
| 冻结 backbone | 只训 head，编码器参数不动 |
| logits | 还没过 sigmoid / softmax 的原始分数 |
| CE / BCE | 多分类互斥用 CE；多标签各自二分类用 BCE |
| GELU / Dropout | 激活函数 / 随机丢弃一部分神经元防过拟合 |
| Dice | 衡量两个区域重叠程度，越接近 1 越好 |
| skip connection | 把高分辨率细节直接接到解码器，补回丢失的边界信息 |
| NRMSE | 归一化误差，≈1 表示和"用平均值猜"差不多 |
| few-shot / one-shot | 只用几张 / 一张标注样本训练 |
| AUROC | 分类综合能力指标，0.5 = 瞎猜，1.0 = 完美 |
