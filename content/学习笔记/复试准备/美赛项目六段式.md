## 2 分钟口述版（首选，先背这个）

老师好。我第二个项目是 2026 年美赛 C 题，研究对象是《与星共舞》这类「裁判分 + 粉丝票」混合淘汰机制。

核心难点是：裁判分能直接观测，但粉丝真实投票观测不到，所以这是一个逆问题。我们把粉丝偏好建成隐变量，用历史裁判分、淘汰结果和当年赛制规则去做贝叶斯反演。

方法上分两套：第 3–27 季是百分比制，反演每周的粉丝投票份额；第 1–2 季和第 28–34 季是排名制，反演潜在人气，再用 Plackett-Luce / Bradley-Terry 映射成粉丝排序；第 28 季以后还要把 bottom-two 和评委救援写进似然。实现上我用 Python 建了 335 个赛季-周面板，用 Dirichlet 先验和 MCMC 采样，并用 R-hat、ESS 做收敛诊断。

在此基础上我们做了反事实回放：固定每周真实参赛集合，每周抽 2000 次后验样本，比较百分比制、排名制和评委救援谁更「偏粉丝」。历史回放里，百分比制淘汰集合命中率是 96.26%，排名制是 75.00%。最后我们提出前期更看粉丝、后期提高评委权重的动态权重方案。

这个项目里我主要负责建模、MCMC 实现、反事实实验和论文撰写。它和我大创项目的共同点是：都要把问题形式化，并且自己把代码跑通、用指标验证假设。

## 六段式详细版（被追问时按段展开）

### 1. 背景

《与星共舞》每周同时看裁判专业分和粉丝投票，再按规则淘汰。公开数据里能看到裁判分和谁被淘汰，但看不到粉丝真实票数。题目要求估计粉丝偏好，并比较不同合并规则会怎样改变淘汰结果。

一句话动机：**粉丝票是隐变量，淘汰结果是观测；我们要在已知规则下反推隐变量，再做规则对比。**

### 2. 数据与设定

- 原始数据：官方赛季数据表（celebrity / week / judge scores / placement）
- 我预处理后得到 **335 个 season-week** 的长表面板
- 两套历史赛制：
  - **百分比制**：Seasons 3–27  
    `combined = 0.5 × judge_pct + 0.5 × fan_share`
  - **排名制**：Seasons 1–2, 28–34  
    `total_rank = judge_rank + fan_rank`  
    Season 28+ 还有 bottom-two + judges save

### 3. 方法

整体是四步：

1. **Task 1 反演粉丝偏好**  
   - 百分比季：Dirichlet 先验 + MCMC，反演每周 `fan_share`  
   - 排名季：反演 latent popularity utility，经 Plackett-Luce / Bradley-Terry 得到排序信号  
   - 用后验预测检查「按这个粉丝偏好，能不能解释真实淘汰」  
   - 用 **R-hat、ESS** 看链是否收敛、有效样本量是否够

2. **Task 2 反事实回放**  
   - 口径是 **weekly replay**：只固定该周真实选手集合，不把反事实结果滚到后面几周  
   - 每周 **2000 次** Monte Carlo，比较 Percent / Rank / Judges Save

3. **Task 3 选手特征**  
   - Ridge 回归 + Bootstrap，看年龄、职业舞伴等因素如何影响裁判偏好和粉丝偏好

4. **Task 4 动态权重方案**  
   - 核心思想：前期更看粉丝参与（评委权重约 0.4），后期提高专业性（评委权重约 0.6），在第 6 周附近平滑过渡

### 4. 我负责什么

与简历一致，可直接说：

- 用 Python 构建 335 个赛季-周面板  
- 实现 Dirichlet 先验、MCMC、Plackett-Luce / Bradley-Terry 反演  
- 做后验预测，以及 R-hat / ESS 诊断  
- 做每周 2000 次 Monte Carlo 反事实回放  
- 参与 Ridge / Bootstrap 特征分析与论文写作  

如果被问「你写代码了吗」：  
> 写了。数据清洗、MCMC 主流程、反事实回放和部分可视化都是我做的，代码在 `code/MCM/Code/` 下面按 Task 1 到 Task 4 分目录。

### 5. 结果（只背这些数字）

| 口径 | 数字 | 怎么说 |
| --- | --- | --- |
| 面板规模 | 335 个 season-week | 预处理后的周级样本数 |
| MC 次数 | 每周 2000 次 | 反事实不确定性传播 |
| 百分比制命中率 | **96.26%（206/214）** | 淘汰集合命中率，k≥1 |
| 排名制命中率 | **75.00%（54/72）** | 淘汰集合命中率，k≥1 |
| 排名制最终淘汰准确率 | 72.73%（40/55） | k=1 时是否命中最终淘汰者 |
| Season≥28 bottom-two | 93.18%（41/44） | 末两位包含率 |
| 规则分歧周 | 106/335 = 31.6% | Percent 与 Rank 淘汰集合不同 |
| 偏粉丝结论 | 约 92.6% | 分歧周里，百分比制更常淘汰粉丝份额更低的人 |

面试时优先报：**335、2000、96.26%、75.00%**。其余被追问再补。

### 6. 不足与改进

1. 粉丝票始终是反演结果，不是真实观测；结论依赖模型假设。  
2. weekly replay 不模拟「若某人没被淘汰，后续周分数会怎么变」，避免不可观测假设，但也限制了长期赛季推演。  
3. 赛制跨年变化大，排名制季节本身更难拟合，所以 75% 低于百分比制并不奇怪。  
4. 若重做：会补更系统的先验敏感性分析，并把 judges save 从确定性版扩展成带参数不确定性的版本。

## 30 秒英文版

Our MCM project studied the mixed elimination system in Dancing with the Stars. Fan votes are unobservable, so we treated fan preference as a latent variable and used Bayesian MCMC to invert it from judge scores and elimination outcomes. We built a panel of 335 season-week records, compared percentage and ranking rules with 2000 Monte Carlo replays per week, and obtained elimination-set hit rates of 96.26% and 75.00%. I was responsible for modeling, implementation and writing. The paper received an Honorable Mention.

## 高频追问速答

| 追问 | 应答要点 |
| --- | --- |
| 什么是隐变量？ | 粉丝真实投票份额观测不到，只能从淘汰结果反推 |
| 为什么用贝叶斯 / MCMC？ | 要的是后验分布不是一个点估计；后验没有封闭解，所以用 MCMC 采样 |
| Dirichlet 先验为什么合适？ | 粉丝份额是和为 1 的比例向量，Dirichlet 正好定义在单纯形上 |
| Plackett-Luce / Bradley-Terry？ | 把潜在人气映射成排序概率的经典模型；BT 可看作 PL 的成对特例 |
| R-hat / ESS 是什么？ | R-hat 看多链是否收敛到同一分布；ESS 看独立有效样本量够不够 |
| 96.26% 和 75% 差这么多？ | 两套赛制不同、难度不同；百分比制更直接，排名制还叠加 bottom-two / 救援，更难 |
| 反事实怎么做的？ | 固定当周选手集合，只换合并规则，用后验样本做 Monte Carlo，不滚动到后续周 |
| 什么叫更偏粉丝？ | 当两种规则淘汰结果不同时，哪个规则更常留下粉丝份额更高的人 |
| 动态权重是什么？ | 前期粉丝权重大一点，后期提高评委权重，平衡观赏性与专业性 |
| 和创新点是什么？ | 不是发明新模型，而是把逆问题、规则机制和反事实评估做成可复现闭环 |
| 和大创有什么关系？ | 一个是医学视觉，一个是不确定性建模；共同点是形式化问题 + 自己写代码验证 |
| 美赛你负责建模还是写论文？ | 建模、实现、实验和论文我都做了，不是只写文字 |
