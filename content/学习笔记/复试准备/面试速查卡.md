## 一、数字口径（绝对不能报错）

| 任务 | 数据集 | 要报的数字 |
| --- | --- | --- |
| DR 二分类 | Diabetic Retinopathy Arranged（训练 4529 / 测试 1135，50:50 均衡） | AP 93.35%、ACC 80.70%、AUC 85.73%、F1 83.58% |
| 血管分割 | DRIVE | Dice 78.17% |
| 微动脉瘤 | IDRiD 微动脉瘤子集（测试 27 张） | **只讲方法，不主动报数字**（评测口径有问题，见下） |

三条铁律：

1. 微动脉瘤那一支**只讲方法**：MSRNet、96×96 patch、19 万训练 patch、stride 20 重叠重建、阈值 0.15。数字一律不主动报
2. **不主动提** IDRiD 上那一版 DR 分级的数字（0.7915），它低于平凡基线，讲不出去
3. 被问"数据不平衡怎么处理"，答"数据本身就是 50:50 均衡的"

**为什么微动脉瘤不能报数字**：0.8185 是"逐像素平均 Dice"，恒等于 `1 - 0.5×(1-准确率)`，只由准确率决定，模型全输出背景时它反而更高，不是分割指标。而真实的 Dice 0.6767 虽然自洽，但反推混淆矩阵后发现评测的"正类像素"占到 62%，与微动脉瘤的稀疏性矛盾，说明当时的 ground truth 加载有问题，**整支指标都不可靠**。

**个人学业数字**：GPA 4.42 / 5.00，专业排名 21 / 191，学分加权平均分 94.32。高等数学 100、数据结构实验 100、概率论 99。

## 五、高频问答（速答版）

| 问题 | 一句话答案 |
| --- | --- |
| 数据集你处理了什么 | 整理成二分类目录、按 8:2 划分、生成标签文件；原图 1024×768 缩放至 224×224 |
| 为什么用 VisionFM 而不是从零训练 | 医学标注数据稀缺，迁移学习大幅降低对标注量的依赖 |
| 微动脉瘤为什么难分割 | 目标只有几个像素，下采样时会直接消失 |
| 微动脉瘤的分割指标是多少 | "这一支是我们最不成熟的部分，评估口径也不够严谨，当时沿用的评测脚本对极小目标不太适用，指标我倾向于不下结论。"（**不要背具体数字**） |
| 数据不平衡怎么处理 | 数据本身 50:50 均衡，不需要额外处理 |
| AP 为什么比 AUC 高 | 测试集均衡，PR 随机基线是 0.50；脚本里 AP 用 macro 平均 |
| 数据不多会不会过拟合 | 基于预训练权重微调；判断要看训练/验证曲线是否分离；官方提示小数据集只需 5 个 epoch |
| Dice 和 IoU 的区别 | Dice = 2\|A∩B\|/(\|A\|+\|B\|)，IoU = \|A∩B\|/\|A∪B\|，单调相关 |
| 大模型辅助解读算创新点吗 | 是工程层面的增强，**不是算法层面的创新** |
| 项目里最有难度的地方 | 小目标分割，说具体的失败尝试和解决思路 |
| 如果重做会怎么改 | ① 按患者分组划分 ② 跨数据集验证 ③ 微动脉瘤改 FROC ④ 与医生对照评估 |

## 六、三个"记不清"的应对模板

**通用开场**："训练是在服务器上做的，日志没有保留下来，这个具体参数我记不太清了。我能确定的是……"

**被问 IDRiD 那一版**："我们最开始在 IDRiD 上做 DR 分级。IDRiD 只有 516 张，Healthy 和 DR-2 各 168 张，但 DR-1 只有 25 张，这个类别基本没法训练；并成二分类后正样本又占 67%，F1 对阈值极其敏感，指标不稳定。所以正式实验换用了更大、类别接近 1:1 的 Diabetic Retinopathy Arranged 数据集。"

**被问学习率等训练细节**：微动脉瘤那一支可以直接答——Adam，学习率 1e-3 跑 150 轮后降到 1e-4，batch 30（这些都在代码里）。
